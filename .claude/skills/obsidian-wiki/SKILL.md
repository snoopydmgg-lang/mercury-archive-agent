# Obsidian Wiki 知识库

基于 Andrej Karpathy LLM Wiki 方法论 + LOL-MVK 架构设计。

> **核心理念**：LLM 是全职图书管理员，不是搜索引擎。Wiki 是持久化、复利的知识制品，而非临时检索的碎片。

---

## 架构（三层）

| 层 | 说明 | 对应目录 |
|----|------|---------|
| **Raw（只读原始层）** | 原始素材，AI 只读不写，不可篡改 | `03_Assets_全局库/raw/` |
| **Wiki（整理后的知识笔记）** | AI 主动提炼、链接、维护的结构化 md 文件 | `03_Assets_全局库/wiki/` |
| **Schema（配置层）** | CLAUDE.md + SCHEMA.md，引导 AI 维护 Wiki 的约定与工作流 | 项目根目录 |

**关键区别**：
- Raw = Source of Truth（只读不变）
- Wiki = LLM 全权编写和维护（人类只策划来源和提问）
- Schema = 让 LLM 成为有纪律的 Wiki 维护者而非通用聊天机器人

## Wiki 笔记格式

每条 wiki 笔记必须包含 frontmatter：

```markdown
---
title: 笔记标题
来源: https://... 或 来源描述
核心观点:
  - 观点1
  - 观点2
适用选题方向:
  - 方向1
  - 方向2
关联笔记:
  - [[wiki/相关文件名]]
录入日期: YYYY-MM-DD
---

## 笔记正文
...
```

## 四个核心操作

### 1. Ingest（摄取）

当用户提供新素材、GetNote 笔记、PDF 内容、网页文章时执行：

1. **读取原始素材** → 保存到 `raw/` 对应目录
2. **提炼关键信息** → AI 提取核心观点、适用选题方向
3. **写入 Wiki** → 按格式生成 .md 文件，放到对应分类
4. **更新 index.md** → 在顶部追加新条目
5. **追加日志** → 在 `index.md` 底部日志区按格式追加：
   ```
   ## [YYYY-MM-DD] ingest | 标题
   ```
6. **建立关联** → 在相关笔记中添加 `[[wiki/文件名]]` 链接

**摄取粒度**：优先逐个摄取（保持参与感），批量摄取也可以。

### 2. Query（查询）

当用户询问选题、竞品、运营问题时执行：

1. **读 index.md** → 找到相关分类
2. **读相关 wiki 文件** → 获取详细信息
3. **综合给出回答** → 带引用、有洞察
4. **重要洞察 → 写回 Wiki** → 如果发现好答案，将其提炼为新 wiki 笔记加入知识库

> **复利原则**：你的每一次探索都应该让知识库变厚。好的分析、对比、洞察，不要消失在聊天历史里，要写回 Wiki。

### 3. Lint（整理/健康检查）

每月或每完成一个大项目后执行：

1. 检查孤立页面（没有被任何笔记引用的页面）
2. 检查过时内容（与新素材矛盾或已被更新的）
3. 检查重复条目（来源相同或标题相似的）
4. 更新 index.md 中的笔记统计数量
5. 补充缺失的关联笔记链接
6. 清理已被完全整合到其他笔记中的冗余条目
7. **清理空洞文件**：删除 `raw/` 和 `wiki/` 中无实质内容的文件（空文件、仅标题/一行、残留模板占位符、失效链接），同步更新 index.md 中的引用

### 4. Log（日志记录）

`index.md` 底部的日志区是 append-only 的时间线记录：

- 格式：`## [YYYY-MM-DD] action | 标题`
- action 类型：`ingest` | `lint` | `update` | `restructure`
- 示例：`## [2026-04-11] ingest | 新增7本书籍笔记`

日志帮助 LLM 理解知识库的演化历史，避免重复工作。

## 查询规则（当你需要从知识库找东西时）

1. **先读 index.md** → 找到相关分类和笔记列表
2. **再读对应 wiki 文件** → 获取详细信息
3. **综合多条笔记给出回答**
4. **如果发现好洞察 → 主动写入 Wiki**（不用等用户说）

---

## 编译流程（GetNote 笔记导入时）

当用户说"编译新笔记"、"从 GetNote 导入"时：

1. 调用 `getnote` skill 获取笔记列表
2. 判断分类 → 选题灵感→选题库 / 运营方法→账号运营 / 个人成长→个人成长
3. 按格式写入 `wiki/` 对应目录
4. 更新 `index.md` 顶部条目 + 底部日志
5. 如果已有同名/同来源文件 → 更新而非新建

---

## 数据分析工作流

当用户提供数据分析文件（xlsx/csv）时：

1. 读取原始数据 → 保存到 `04_数据分析结果/`
2. 分析数据 → 提炼洞察
3. **有价值内容** → 写入 `wiki/账号运营/`（复盘洞察类）
4. **原始数据立即删除**（洞察比文件重要，不囤积）

## 注意事项

1. **Raw 只读** - 原始素材永远不修改，保证信息来源可信
2. **先读 index.md** - 回答问题前先找相关笔记，不随机抓取
3. **双向链接** - 用 `[[wiki/文件名]]` 建立关联，形成知识图谱
4. **探索结果写回 Wiki** - 好的洞察不要让它消失在聊天里
5. **不需要向量数据库** - 轻量化架构，靠 index.md + 结构化笔记 + 链接工作
6. **Schema 是活的** - CLAUDE.md 和 SCHEMA.md 随经验积累而更新，不是固定不变的
