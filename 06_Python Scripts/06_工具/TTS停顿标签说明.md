# TTS 停顿标签说明

## ⚠️ 重要说明

**Kitta AI API 不支持停顿标签**。文案中的 `<#x#>` 标签会被预处理器**自动移除**，不会传递给 API。

## 为什么保留停顿标签语法？

虽然 Kitta AI 不支持，但停顿标签在文案编写阶段仍然有价值：

1. **文案规范化**：标记出需要停顿的位置，方便后期剪辑
2. **节奏可视化**：让文案作者清楚地看到语音节奏
3. **未来兼容性**：如果切换到支持停顿的 TTS 引擎，文案无需修改
4. **后期制作指南**：剪辑师可以根据标签手动添加静音片段

## 停顿标签清洗规则

预处理器会对停顿标签执行以下操作：

### 1. 边界修正
- `<#0.001#>` → `<#0.01#>` （小于最小值，修正为 0.01）
- `<#100#>` → `<#98.99#>` （大于最大值，截断为 98.99）
- `<#1.23456#>` → `<#1.23#>` （精度修正，保留两位小数）

### 2. 连续标签合并
- `<#1#><#2#>` → `<#3.0#>` （相加）
- `<#50#><#50#>` → `<#98.99#>` （相加后超过最大值，截断）

### 3. 位置清理
- `<#1#>你好世界` → `你好世界` （移除开头标签）
- `你好世界<#1#>` → `你好世界` （移除结尾标签）
- `你好 <#1#> 世界` → `你好 世界` （移除孤立标签）

### 4. 最终移除
清洗后的标签会被**完全移除**，不会传递给 API。

## 实际效果

**输入文案**：
```
{emotion:excited}拉开这本书<#0.3#>等等，这只鸟怎么会动？
```

**预处理后**：
```
[excited]拉开这本书 等等，这只鸟怎么会动？
```

**传递给 API**：
```
[excited]拉开这本书 等等，这只鸟怎么会动？
```

停顿标签 `<#0.3#>` 被替换为空格。

## 如何实现停顿效果？

### 方案 1：使用标点符号（推荐）
```
拉开这本书，等等，这只鸟怎么会动？
```
TTS 引擎会自然地在逗号、句号处停顿。

### 方案 2：调整语速
```python
generate_tts(
    text=text,
    output_path=output_path,
    speed=0.9  # 降低语速，增加停顿感
)
```

### 方案 3：后期剪辑
1. 在文案中保留停顿标签 `<#0.5#>`
2. 生成音频后，根据标签位置手动插入静音片段
3. 使用 Audacity、Adobe Audition 等工具

### 方案 4：分段生成
```python
# 分段生成，中间插入静音
segment1 = "拉开这本书"
segment2 = "等等，这只鸟怎么会动？"

generate_tts(segment1, "part1.wav")
generate_tts(segment2, "part2.wav")

# 使用 pydub 合并音频并插入静音
from pydub import AudioSegment

audio1 = AudioSegment.from_wav("part1.wav")
audio2 = AudioSegment.from_wav("part2.wav")
silence = AudioSegment.silent(duration=500)  # 500ms 静音

final = audio1 + silence + audio2
final.export("final.wav", format="wav")
```
