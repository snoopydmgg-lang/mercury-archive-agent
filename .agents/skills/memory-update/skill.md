# Memory 更新工具

## 功能

每次任务完成后，**自动**将关键信息写入 MEMORY.md，无需用户请求。

## 触发时机

以下情况**必须**更新 MEMORY.md：
- 完成任务后
- 发现新的工作规律或偏好
- 用户提供了重要背景信息
- 遇到错误并找到解决方案
- 任何值得保存的新认识

## MEMORY.md 结构

```
## [主题分类]

### [日期]
- **事实/决定**：具体内容
- **为什么**：原因背景
- **如何应用**：对未来工作的指导
```

## 更新流程

### 1. 判断是否值得记录

问自己：
- 未来还会遇到类似情况吗？
- 这个信息对理解用户有帮助吗？
- 这是一个重复出现的模式吗？

如果"是"，就记录。

### 2. 写入正确的位置

| 信息类型 | 写入位置 |
|----------|----------|
| 用户偏好/习惯 | `MEMORY.md` 的 `user` 部分 |
| 项目进展/决策 | `MEMORY.md` 的 `project` 部分 |
| 技术教训/错误修复 | `MEMORY.md` 的 `reference` 部分 |
| 外部系统信息 | `MEMORY.md` 的 `reference` 部分 |

### 3. 格式要求

每个记忆条目包含：
- **标题**：简洁的事实描述
- **为什么**：解释原因
- **如何应用**：对未来工作的指导

### 4. 示例

用户成功完成了 PPT 自动化，发现了一个脚本 bug：

```
### 2026-04-10
- **PPT text runs bug**：当文本被拆分成多个 runs 时，替换会失败
- **为什么**：Python pptx 库中段落文本可能分散在多个 run 对象里
- **如何应用**：写 PPT 脚本前先用 `unpack_xml()` 检查结构，批量替换用 `set_paragraph_text()` 而非逐 run 替换
```

## 触发关键词

当用户说以下话时使用此 skill：
- "更新记忆"
- "写入 memory"
- "记录一下"
- "记住这个"
- "把...写入 MEMORY.md"
- 任何任务完成后的场景（**自动触发，不需要用户说**）

## 注意事项

1. **自动更新是默认行为**，不要等用户要求
2. **简洁优先**：一条记忆不超过3行
3. **包含行动指导**：光记录事实不够，要写清楚"如何应用"
4. **不要重复**：如果 MEMORY.md 已有类似内容，更新而非添加
