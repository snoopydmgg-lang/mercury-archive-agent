# 自动化定时任务说明书

最后更新：2026-05-21

---

## 概述

本文档描述水星艺术馆项目的 7 个定时自动化任务。每个任务可交由 AI Agent（Claude Code / Codex）按 cron 调度执行。

数据核心：`.cheat/state.json` + `06_Python Scripts/billing_cache.json`

---

## 1. 早间简报

**频率**：每天 9:00 | **关键程度**：必装

读取 `state.json` 和 `billing_cache.json`，输出早间简报：

- **Buffer 状态**：还剩几篇未发布？按 `target_publish_cadence_days` 还能撑几天？如果 < 2 天标红。
- **T+3 复盘提醒**：检查 `pending_retros` 中每条预测的 `published_at`，列出今天到期的。
- **发布节奏**：`last_published_at` 距今天数，是否超过 cadence？超过几天？
- **账单**：今日 / 本月消费各多少？HUD 显示是否正常？
- **收件箱**：`00_InBox_收件箱/` 中有无待处理文件？
- **选题池**：`candidates.md` 还剩几条候选？

> 只报告，不执行任何操作。

---

## 2. 每日抓热点

**频率**：每天 10:00 | **关键程度**：必装

执行 `/cheat-trends`，抓热门话题，去重打分后写入 `candidates.md`。

完成后报告：
- 新增候选条数
- Top 3 选题及其 composite 分数
- `candidates.md` 当前总条数

---

## 3. T+3 复盘检查

**频率**：每天 8:30 | **关键程度**：必装

读取 `state.json` 的 `pending_retros` 数组。对每条预测文件：

1. 读取 `published_at` 字段
2. 计算距今天数
3. 判断是否 ≥ 3 天（到达 T+3 窗口）

到期的处理：
- 提醒去抖音后台导出该视频的**流量数据**和**内容吸引力数据**，放到收件箱
- 执行 `/cheat-retro <prediction 文件路径>`

输出清单：视频名、发布时间、已过天数、是否到期。

> 全部未到期则静默通过。

---

## 4. 账单同步提醒

**频率**：每 2 天 18:00 | **关键程度**：推荐

检查 `billing_cache.json` 的 `updated` 字段，计算距上次同步已过小时数：

- **< 48 小时**：静默通过。
- **≥ 48 小时**：提醒去 DeepSeek 后台导出当月账单 CSV（`amount-*.csv` + `cost-*.csv`）放到收件箱，然后运行：
  ```
  python 06_Python Scripts\06_工具\token_tracker.py
  ```

---

## 5. 收件箱清理

**频率**：每周日 20:00 | **关键程度**：推荐

列出 `00_InBox_收件箱/` 中所有文件和子目录，对每个文件：

- 最后修改时间 > 7 天 → `[建议删除]`
- 文件名含 `zip` / `csv` / `tmp` / `temp` → `[临时文件，建议删除]`
- 文件名含 `知识库` / `资料` / `README` → `[可能重要，需确认]`

输出候选删除清单（文件名、修改时间、删除原因），**等用户确认后再删**。

---

## 6. Wiki 知识库健康检查

**频率**：每周日 21:00 | **关键程度**：可选

运行 Wiki Lint：

```
python 06_Python Scripts\06_工具\wiki_lint.py
```

输出摘要：总检查项数、通过/警告/错误数量、需修复问题列表。

> 全部通过则输出 "知识库健康状态正常"。

---

## 7. 周报生成

**频率**：每周日 22:00 | **关键程度**：推荐

汇总本周数据，来源：`state.json`、`billing_cache.json`、本周预测/复盘文件、`candidates.md`。

### 报告结构

**本周发布**
- 发布条数，每条播放量 / 5s 完播率 / 互动
- 实际播放 vs 预测 bucket，偏差方向

**本周消费**
- DeepSeek 本周消费 / 累计本月 / 月末预测
- 与上周环比

**校准状态**
- rubric 版本和校准样本数
- prediction 准确率趋势（是否连续偏差？需要 bump？）

**选题池**
- candidates 剩余条数
- 上周抓热点次数

**下周建议**
- Buffer 是否充足？
- 需要优先处理的 retro？
- 需要升级什么？

## 实现方式

### Cron 触发

使用 Claude Code 的 `/loop` 或 CronCreate 机制调度。示例：

```
/loop 1d 早间简报
/loop 1d 抓热点
/loop 1d T+3复盘检查
```

### 前置依赖

- `.cheat/state.json` schema ≥ 1.4
- `billing_cache.json` 存在
- Python 路径：`C:/Users/Administrator/AppData/Local/Programs/Python/Python310/python.exe`
- cheat-on-content skill 集已安装

### 任务源文件

原始 task 定义位于 `00_InBox_收件箱/task_*.md`，Wiki 版本为规范化副本。修改定时任务逻辑时，Wiki 版本为权威参考。
