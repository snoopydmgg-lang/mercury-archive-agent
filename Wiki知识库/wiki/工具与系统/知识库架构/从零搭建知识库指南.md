# 从零搭建个人知识库：完整指南

> 适用对象：Claude Code + Obsidian
> 语言：中文
> 目标：在任意项目目录下，搭建一套结构清晰、可被 AI 持续访问的个人知识库
> 预计耗时：Claude Code 执行约 5-10 分钟 + Obsidian 配置 10-15 分钟

---

## 一、知识库是什么，为什么这样设计

这套知识库适用于**任何需要长期积累知识的场景**，解决三个普遍问题：

1. **素材太散**：文章、笔记、调研资料堆在各处，需要时找不到
2. **知识不积累**：每次处理类似问题都从头来，过往经验无法复用
3. **AI 无法记住**：每次开新 session，AI 不知道你已经积累的上下文、结论和洞察

**适用场景举例**：
- 研究人员：管理论文笔记、实验记录、文献综述
- 产品经理：沉淀竞品分析、用户调研、需求背景
- 开发者：记录技术选型、架构决策、调试经验
- 知识工作者：整理学习笔记、方法论、项目复盘
- 内容创作者：管理选题背景、参考素材、创作经验

**设计核心**：物理隔离的两层架构 + 严格的空间/时间分离 + AI 自动化编译

```
raw/     ← 原始素材层（只读，永不修改）
wiki/    ← 萃取知识层（精华，网状引用）
index.md ← 空间拓扑（目录索引，静态）
log.md   ← 时间序列（操作日志，Append-only）
```

**Karpathy 哲学**：像编译代码一样编译知识
- 不依赖向量数据库，直接让 LLM 读写 Markdown 文件
- 对于个人知识库规模（100-1000 篇文章），效果不比向量检索差
- 简单、低成本、易维护

## 二、第一步：规划你的分类体系

**在创建目录前，先回答这三个问题：**

1. 你的知识主要来自哪里？（网页、论文、会议记录、自己的分析...）
2. 你最常查询哪类问题？（技术方案、竞品信息、历史决策...）
3. 按什么维度分类最自然？（按主题、按项目、按时间、按来源...）

**通用分类模板**（按你的业务替换，规则保持不变）：

```
raw/                        ← 原始输入层（只读）
├── [主题分类A]/            ← 例：技术学习 / 市场调研 / 竞品分析
├── [主题分类B]/
├── [主题分类C]/
│   └── [子分类]/           ← 需要细分时加一层
└── Clippings/              ← 网页剪报统一归档

wiki/                       ← 萃取输出层（精华）
├── [知识分类A]/            ← 与 raw/ 分类可以对应，也可以重新组织
├── [知识分类B]/
└── 知识库架构/             ← 固定保留：存放本指南和元文档
```

**各领域分类示例**：

| 领域   | raw/ 分类示例       | wiki/ 分类示例      |
| ---- | --------------- | --------------- |
| 软件开发 | 技术文档、架构设计、Bug记录 | 技术选型、架构决策、经验总结  |
| 产品管理 | 用户访谈、竞品截图、需求文档  | 竞品分析、用户洞察、产品方法论 |
| 学术研究 | 论文原文、实验数据、会议记录  | 文献综述、理论框架、研究进展  |
| 内容创作 | 参考素材、背景资料、爆款案例  | 创作方法论、选题分析、风格指南 |
| 投资分析 | 财报数据、行业报告、新闻剪报  | 公司分析、行业趋势、投资逻辑  |

> 规则只有一条：**raw/ 是你放进去的原始材料，wiki/ 是你（或 AI）从中提炼的洞察。**

````markdown
## 物理架构规范（空间拓扑 × 时间序列）

| 文件/目录 | 职责 | 性质 |
|---------|------|------|
| `index.md` | 知识库总目录、Wiki 页面索引 | 空间拓扑，新增 Wiki 时更新 |
| `log.md` | 操作日志时间序列 | Append-only，只追加不修改 |

├── [你的分类]/
└── 知识库架构/
index.md      # 知识库总目录（空间拓扑）
log.md        # 操作日志（时间序列，Append-only）
SCHEMA.md     # 本文件（知识库规则）
```

## 原始素材规则

**核心原则**：用户放入知识库的文件 → `raw/`；Wiki 只存放萃取的摘要文档。

1. 所有外部文件直接存入 `raw/` 对应分类，文件名保持不变
2. `raw/` 文件夹内容只读，永远不修改或移动
3. 从 raw 内容萃取精华 → 生成摘要文档放入 `wiki/`

**raw 文件命名格式**（新建时）：`YYYYMMDD_主题关键词.md`
示例：`20260411_竞品A产品分析.md`

**禁止把原始文件放进 Wiki。**

---

## Wiki 笔记格式

每条 wiki 笔记必须包含以下元数据头：

```yaml
---
title: 笔记标题
来源: https://...（或"手动整理"）
核心观点:
  - 第一条核心洞察（一句话）
  - 第二条核心洞察
  - 第三条核心洞察
适用场景:
  - 场景一
关联笔记:
  - [[wiki/账号运营/抖音账号数据复盘洞察]]
录入日期: YYYY-MM-DD
---
```

### 各字段说明

| 字段 | 说明 |
|------|------|
| `title` | 标题，能一眼看出主题 |
| `来源` | 原始链接或"手动整理" |
| `核心观点` | 3-5 条最核心的洞察，每条一句话 |
| `适用场景` | 这条知识在什么情况下有用 |
| `关联笔记` | 用 `[[wiki/个人成长/图层工作法]]` 格式链接相关笔记 |
| `录入日期` | 格式 `YYYY-MM-DD` |

## 分类规则

| 分类 | 存放内容 | 命名规则 |
|------|----------|----------|
| `wiki/[分类A]/` | [说明A] | 简洁主题名.md |
| `wiki/[分类B]/` | [说明B] | 简洁主题名.md |

| `raw/[分类A]/` | 原始资料（只读） | 原始文件名不动 |

## Compile（编译）流程

每次处理新素材时按以下步骤执行：

**第一步：接收原始文件**
- 接收用户放入的文件，或从工具抓取最新内容

**第二步：放入 raw/ 对应分类**
- 直接存入 `raw/` 对应分类，文件名不动
- 不修改、不移动、不删除

**第三步：生成萃取文档（如有必要）**
- 从 raw 内容提炼关键信息
- 生成简洁命名的摘要文档
- 放入 `wiki/` 对应分类，格式遵守 Wiki 笔记格式

**第四步：更新 index.md**
- 在对应分类下增加新 wiki 页面的链接
- raw 文件不列入 wiki 区域，只在"原始资料"表中简述分类

**第五步：追加 log.md**
- 格式：`## [YYYY-MM-DD] 动作类型 | 描述`
- 示例：`## [2026-04-13] compile | 新增 3 条竞品分析笔记`

---

## Wiki 页面拓扑规范（网状交叉引用）

**页面类型**：
- **实体页** — 具体对象（工具、产品、人物、项目）
- **概念页** — 抽象概念（方法论、原则、框架）
- **对比页** — 多维对比分析（工具选型、方案对比）

**强制引用规则**：
- 新建 Wiki 页面时，必须扫描 `index.md` 中所有现有页面
- 使用 `[[页面名称]]` 或相对路径建立与现有页面的交叉引用
- 每个页面至少有一条出站链接（禁止孤立页面）

---

## Query 流程与 Write-back 闭环

**标准 Query 流程**：
1. 读取 `index.md` 定位相关 wiki 页面
2. 读取对应 wiki 文件
3. 综合多条笔记给出回答
4. 若回答涉及多维对比或深度推演 → 触发 Write-back

**Write-back 触发条件**（满足任一即触发）：
- 复杂查询（跨 3 个以上 wiki 页面的综合分析）
- 高价值对比（工具选型、方案决策）
- 原创推演（非直接摘取，产生新洞察）

**Write-back 执行步骤**：
1. 将推演结果沉淀为独立 Wiki 页面
2. 在页面内使用 `[[交叉引用]]` 连接相关现有页面
3. 追加 log.md：`## [YYYY-MM-DD] query-writeback | 页面名称`
4. **不更新 index.md**（index.md 为静态索引，只在主动 compile 时更新）

---

## 去重规则（防止重复导入）

每次 compile 前必须检查：
1. 读取 log.md 获取所有已导入笔记的标题列表
2. 逐条对比标题或来源链接
3. 来源链接或标题已存在于 `wiki/` 任意文件中 → 跳过，不重复写入
4. compile 结束后在日志中注明：本次新增 X 条，跳过重复 X 条

**来源唯一性原则**：每条 wiki 笔记的【来源】字段是唯一标识；写入前先搜索是否已存在相同来源，已存在则更新原文件而非新建。

---

## 维护规则（每月一次）

1. 检查孤立页面（没有被任何笔记引用的页面）→ 补充交叉引用
2. 检查过时内容（与新素材矛盾的）→ 标记 `[OUTDATED]`
3. 更新 index.md 中的笔记统计数量
4. 检查 index.md 链接是否都有效 → 修复死链
````

## 七、第六步：创建知识库运作指南（第一条 Wiki）

**指令**：在 `wiki/知识库架构/` 下创建文件 `知识库运作指南.md`，内容如下：

````markdown

来源: 手动整理
核心观点:
  - 知识库的核心价值是让 AI 在每次 session 中都能访问积累的领域知识
  - raw（只读原始层）与 wiki（萃取知识层）的物理隔离是防熵的关键
  - index.md 管空间，log.md 管时间，二者严格分离
关联笔记:
  - （首条笔记，暂无关联）
录入日期: [今天日期]
---

## 知识库核心理念

**知识是工作的副产品，而非目的。**

每次调研、分析、决策产生的洞察，都应该沉淀到 wiki，而不是留在聊天记录里消失。

### 两条铁律

1. **raw 只读**：放进来的原始文件永远不动，AI 只从中提炼，不修改
2. **wiki 只增**：wiki 页面只增不删，错误的页面打标记 `[OUTDATED]`，不删除

---

## 物理架构

```
index.md  ←→  空间拓扑（What exists, Where）
log.md    ←→  时间序列（What happened, When）
raw/      ←→  原始物理层（Input, Read-only）
wiki/     ←→  萃取逻辑层（Output, Network）
```

---

## 标准工作流

### 输入新素材时（Compile 流程）

1. 接收文件 → 放入 `raw/` 对应分类（文件名不动）
2. 判断是否值得萃取（有新洞察？有复用价值？）
3. 值得萃取 → 在 `wiki/` 对应分类创建摘要文档
4. 更新 `index.md`（添加 wiki 页面链接）
5. 追加 `log.md`（记录本次操作）

### 被查询时（Query + Write-back 流程）

1. 读 `index.md` → 定位相关 wiki 页面
2. 读 wiki 页面 → 综合多条笔记回答
3. 若产生新洞察（跨 3+ 页面分析 / 原创推演）→ Write-back
4. Write-back：新建 wiki 页面 + 交叉引用 + 追加 log.md

---

## 禁止事项

- 禁止修改 `raw/` 下任何文件
- 禁止删除 `wiki/` 下任何页面（标 `[OUTDATED]` 代替删除）
- 禁止在 `index.md` 写入时间日志（时间归 `log.md`）
- 禁止在 `log.md` 写入空间目录（空间归 `index.md`）
- 禁止创建无出站链接的孤立 wiki 页面
````

## 九、后续：导入第一批素材

### 9.1 把现有文件迁移进来

```
指令示例：
将以下文件放入 raw/ 对应分类（文件名保持不变）：
- [你的文件1] → raw/[分类A]/
- [你的文件2] → raw/[分类B]/

然后按 SCHEMA.md 的 Compile 流程处理每个文件。
```

### 9.2 判断每个文件是否需要萃取

```
需要萃取的条件（满足任一）：
- 包含可复用的方法论或原则
- 包含对比分析或决策依据
- 包含背景信息（下次遇到同类问题会用到）
- 包含工具/流程的使用经验

不需要萃取的情况：
- 纯原始数据（CSV、截图、图片、视频）
- 一次性参考，无复用价值
- 与已有 wiki 页面高度重复
```

### 9.3 建立第一批 Wiki 页面（优先级排序）

| 优先级 | 页面类型 | 通用示例 | 说明 |
|--------|----------|---------|------|
| P0 | 规范/原则类 | 工作规范.md、设计原则.md | 频繁被引用的底层规则 |
| P0 | 方法论类 | 核心方法论.md、工作流程.md | 指导日常决策的框架 |
| P1 | 分析/洞察类 | 竞品分析.md、行业趋势.md | 调研后产生的结构化洞察 |
| P1 | 工具指南类 | 工具链使用指南.md | 工具配置和使用经验 |
| P2 | 背景资料类 | 项目背景.md、领域入门.md | 了解上下文的基础知识 |

## 十、日常维护指令

### 每次任务结束后

```
1. 检查是否有新文件需要放入 raw/
2. 检查本次任务是否产生了值得 Write-back 的洞察
3. 追加 log.md 记录本次操作
4. 如有新 wiki 页面，更新 index.md
```

### 每月一次

```
1. 检查 wiki/ 下是否有孤立页面（无出站链接）→ 补充交叉引用
2. 检查 index.md 链接是否都有效（对应文件存在）→ 修复死链
3. 检查 log.md 是否混入了非日志内容 → 清理
4. 统计 wiki/ 页面数量，更新 index.md 说明
```

## 十一、Obsidian 配置（推荐）

### 11.1 安装 Obsidian

**下载地址**：https://obsidian.md/download
- 支持 Windows、macOS、Linux 全平台
- 免费使用，数据存储在本地

**创建 Vault**：
1. 打开 Obsidian
2. 点击「创建」新建仓库
3. 选择你的知识库文件夹（已创建的目录）
4. 命名你的知识库

---

### 11.2 安装 Claudian 插件

**步骤1：安装 BRAT 插件管理器**
1. 打开 Obsidian 设置 → 社区插件
2. 关闭"安全模式"
3. 点击"浏览" → 搜索"BRAT"
4. 安装并启用 BRAT

**步骤2：通过 BRAT 安装 Claudian**
1. 按 `Ctrl/Cmd + P` 打开命令面板
2. 输入"BRAT: Add a beta plugin"
3. 在弹出的对话框中输入：`https://github.com/YishenTu/claudian`
4. 选择版本（默认选择最新版本）
5. 点击"添加"并确认安装
6. 在插件列表中找到 Claudian 并启用

**环境配置**：
- Claudian 会自动读取 CC Switch 的配置
- 不需要在 Claudian 中重复配置环境变量
- 只需在 CC Switch 中配置好 API Key 和模型即可

---

### 11.3 安装 Web Clipper（可选）

**用途**：一键将网页文章保存为 Markdown

**安装方式**：
- 浏览器扩展商店搜索"Obsidian Web Clipper"
- 安装后配置保存路径：`raw/Clippings/`

---

### 11.4 配置图片管理（可选）

**插件**：Custom Attachment Location

**安装步骤**：
1. 设置 → 社区插件 → 搜索"Custom Attachment Location"
2. 安装并启用

**配置要点**：
1. Markdown URL 格式：填写标准 Markdown 图片路径
2. 附件重命名模式：选择"全部"
3. 内部链接类型：选择"基于当前笔记的相对路径"

**效果**：
- 图片自动存入 `assets/` 文件夹
- 重命名笔记时，图片文件夹和链接自动同步更新
- 图片链接为标准 Markdown 格式

### 11.5 配置 GitHub 自动同步（推荐）

**步骤1：创建 .gitignore**
在知识库根目录创建 `.gitignore` 文件：
```
.obsidian/workspace.json
.obsidian/workspace-mobile.json
```

**步骤2：安装 Git 插件**
1. 设置 → 社区插件 → 搜索"Git"
2. 安装并启用

**步骤3：配置自动同步**
1. 点击插件"选项"
2. 配置：
   - Auto commit and push after stopping file edits：改为 1 分钟
   - Pull on startup：勾选

**效果**：
- 停止编辑1分钟后自动同步到 GitHub
- 启动时自动拉取最新版本
- 永不丢失，随时回溯

## 十二、常见错误与修复

| 错误 | 症状 | 修复方法 |
|------|------|---------|
| 原始文件被修改 | raw/ 下的文件内容被改动 | 从 git 还原；后续建立 raw/ 只读保护 |
| 日志混入 index.md | index.md 里有 `## [日期]` 格式内容 | 剪切日志条目 → 粘贴到 log.md |
| wiki 孤立页面 | 某页面没有任何出站链接 | 扫描 index.md 找相关页面 → 添加 `[[引用]]` |
| 重复导入 | wiki/ 下出现内容相同的两个文件 | 保留更完整的一个 → 在 log.md 记录合并操作 |
| index.md 失效链接 | 链接指向的文件已不存在 | 找到对应 wiki 文件 → 修复路径 |
| wiki 页面越来越长 | 单个 wiki 文件超过 500 行 | 拆分为多个子页面，用 `[[引用]]` 串联 |
